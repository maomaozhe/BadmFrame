# ADR 0003：自动剪掉死球时间的启发式方案

## 状态

已暂停：真实观看效果差，不作为后续主路线

## 复盘结论

该方案已实现并用真实视频试跑，但用户观看后反馈剪辑效果很差、结果混乱。结论是：**仅靠全局画面运动量 + 音频能量 + 状态机，无法可靠识别羽毛球有效回合和死球时间**。

后续不要继续把主要精力放在调运动阈值、调缓冲秒数、调分位数上。该实现可以保留为实验基线、测试支架或辅助特征，但不能作为 BadmFrame 自动剪辑的核心方案。

## 背景

BadmFrame 的核心工作流是“导入 -> 浏览 -> 打标记 -> 裁剪 -> 导出 -> 归档”。用户希望进一步减少长视频中的无效时间，尤其是下网后捡球、走回发球位、等待、聊天、重新准备等片段。

“自动识别精彩片段”如果直接作为目标，会过早进入主观判断和大模型依赖：不同用户对精彩的定义不同，业余视频机位、光照、声音和遮挡也不稳定。MVP 更适合先解决更确定的问题：识别有效回合，剪掉死球时间。

## 原决策

MVP 智能剪辑定义为：**自动识别有效回合区间，剪掉明显死球时间，并生成可编辑的自动剪辑草稿**。

第一版不做破坏式自动删除，不直接覆盖原视频，不把“精彩片段识别”作为核心承诺。系统生成候选保留片段和剪掉片段，由用户确认、恢复或微调后导出。

### 第一版算法

采用启发式特征和状态机，不引入训练模型：

- 低频抽帧，计算相邻帧运动量。
- 提取音频能量和峰值密度，辅助判断击球、脚步、喊声等活动。
- 使用视频内部分位数做自适应阈值，避免固定阈值受球馆、机位、曝光影响。
- 用状态机识别有效回合：连续高活动进入回合，连续低活动退出回合。
- 合并短间隔，过滤过短噪声片段，并给每段前后加缓冲。

### 产品形态

- 分析完成后生成“自动剪辑草稿”。
- 时间线上显示保留段和剪掉段。
- 用户可以恢复误剪片段、删除误保留片段、微调边界。
- 导出时按确认后的保留段拼接视频。

## 影响

- Web 后端优先实现，复用 FastAPI + Celery + FFmpeg。
- iOS 后续可用 AVFoundation 做轻量版，但不阻塞 Web MVP。
- 数据模型需要表达自动分析结果、候选片段、置信度和用户确认状态。
- UI 需要把自动结果作为建议，而不是不可逆编辑。

## 成功标准

- 30-40 分钟固定机位羽毛球视频可在几分钟内完成分析。
- 能剪掉大部分明显捡球、等待、走位准备时间。
- 不误删主要回合；误剪时用户能快速恢复。
- 自动剪辑结果可以导出为连续视频。

## 不做

- 不在 MVP 中训练专用高光模型。
- 不自动判断“好球”“精彩球”“失误复盘价值”。
- 不默认做球路追踪、姿态识别、球场线识别。
- 不直接删除或改写原始视频。

## 后续方向

- 重新定义可验证目标：先做回合边界标注/半自动确认，而不是直接自动剪掉。
- 建立带人工标注的评估集，再比较任何算法。
- 引入更强语义信号，例如球员/球场区域、击球声事件、发球/回合结束模式，而不是全局运动量。
- 后续如继续自动化，应先产出可解释的候选边界和置信度，不直接导出成最终剪辑。
