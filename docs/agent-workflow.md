# Agent 工作流

本文记录 BadmFrame 的协作规则。入口和当前状态见 [AGENTS.md](../AGENTS.md)。

## 开始前

- 非简单任务先读 `AGENTS.md`，再按任务选择产品、架构、视频流程或 ADR，不要固定全量阅读。
- 先运行 `git status --short --branch`，识别当前分支、用户未提交改动和未跟踪文件。
- 先检查当前仓库，再假设结构、命令或技术栈；不要凭历史记忆写状态。
- 开始长任务前明确本次目标、范围、预计验证方式和不做的内容。

## 工作中

- 变更范围贴合用户请求，优先小步修改。
- 遵循既有目录、命名、状态管理和测试模式。
- 行为变化配套相关测试；无法运行时说明原因。
- 命令、架构、产品行为、真实项目状态或工作流变化时同步文档。
- 保留用户变更和无关文件，不做破坏性清理。
- 不把历史计划当作当前事实；`tasks/` 下计划可作为追溯材料，当前状态以 `AGENTS.md` 和对应领域文档为准。

## 文档同步

- 项目事实、主路线、常用命令或 Agent 入口变化：更新 `AGENTS.md`。
- 产品范围变化：更新 `docs/product.md`。
- 架构、模块边界或数据流变化：更新 `docs/architecture.md` 和相关 ADR。
- 视频处理、自动剪辑、回合切分方案变化：更新对应领域文档。
- 已被后续实现取代的计划内容可以标为历史或删掉冲突段落，但不要删除 ADR 和有价值的 handoff 记录。

## ADR 触发

显著改变以下内容时，在 `docs/decisions/` 新增 ADR：

- 应用平台或框架。
- 视频处理引擎或导出精度策略。
- 项目文件格式或存储布局。
- 后台任务、队列、并发模型。
- 跨端同步或用户系统。

文件名格式：`0003-short-decision-title.md`。

## 验证

- iOS：优先 `xcodebuild ... CODE_SIGNING_ALLOWED=NO build` 验证编译；真机签名问题单独说明。
- Web 前端：至少运行 `npm run build`；涉及交互时考虑 `npm run test:e2e`。
- Web 后端：优先使用项目虚拟环境运行 `./.venv/bin/pytest`。
- 模型层：优先运行相关 `model/tests` 或 dry-run 管线；涉及 GPU 推理时说明硬件和耗时前提。
- 文档-only 改动通过链接、命令、状态一致性和 `git diff --check` 验证。

## 完成说明

结束时按以下口径说明：

```text
目标：
改动：
验证：
未验证：
剩余风险/下一步：
```

## Handoff 模板

长任务、中断任务或跨 session 交接时，在回复或任务文档中留下：

```text
分支/commit：
工作区状态：
已完成：
验证结果：
阻塞/风险：
下一步：
```
